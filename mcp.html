ABefore: no connection

An assistant is asked about one of Kettlewick's orders:

“Was order 1182 charged twice? What should we do about it?”

It has never seen Kettlewick's order list. With no connection it can only say it cannot see the order — or guess.

BConnect to the Kettlewick server

Kettlewick offers its support data through an MCP server. When an assistant connects, the first thing it does is ask the server: what can I use here?

CUse what the server offers

In a real assistant, the model chooses which of these to use and when. Here you press the buttons it would press. Press all three.

DAsk for something that is not on the list

The customer wants a refund. Tell the server to issue one.

EAfter: hand it to a model

This is what the assistant now has to work with: the same question, plus what came back through the connection. Copy it into any chatbot, or open the expected answer.

See the messages that crossed the plug (0)

Every MCP connection is messages like these, in the same format whichever assistant and whichever system are on the two ends. That shared format is the whole idea.
